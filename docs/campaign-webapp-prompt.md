| ② | 고객 인사이트 도출 | 인사이트 3행 × [문장 / 근거 / 유형(경험·가치·혜택)] + 가장 강한 인사이트·이유 + 경쟁사가 안 건드린 인사이트 | 문장 형식 "[상황]일 때 [행동]하는데 [이유] 때문에 [불만·욕구]를 느낀다" 가이드 |

| ⑤ | 채널 믹스 | 채널 7행(인스타·유튜브·틱톡·인플루언서·라이브커머스·앱/카톡·오프라인, 행 추가/이름 변경 가능) × [사용 / 역할(인지·관심·행동·전환) / 콘텐츠 / 예산 % / 목표] | 예산 % 합계 = 100, 미사용 채널 0% |
| ⑥ | IMC 고객 여정 | 7단계 × [채널·접점 / 메시지 / 고객 행동 / 다음 단계 장치] + 반복 메시지 · 끊기는 지점 | ③ 슬로건을 상단에 고정 표시 |
| ⑦ | 운영계획 | 기간·장소·협력 브랜드·인력 × [내용 / 근거] + 3시기(도입·집중·마무리) × [오프라인 / 온라인 / 예상 방문객] | 시기별 방문객 합계 표시 |
| ⑧ | 예산 배분 | 항목 7행 × [비중 / 금액 / 세부 / 이유] + 총예산 + 1인당 획득 비용 | 비중 합 100, 금액 = 총예산×비중 자동계산, ⑤ 디지털·인플루언서 비중과 불일치 경고, 1인당 비용 = 총예산 ÷ ①주 목표 수치 |
| ⑨ | KPI 설정과 측정 | 퍼널 5단계(인지·관심·행동·전환·관계) × [주·부 / KPI / 현재값 / 목표값 / 측정 방법·시점] + 검증 질문 2개 | 주 KPI 1개, ① 주 목표와 같은 숫자인지 확인 |
| ⑩ | 기획안 1페이지 | 8칸(배경·타깃·명칭·스토리·채널/IMC·운영·예산·KPI) — **새로 쓰지 않고 ①~⑨에서 옮겨 담기** | ①~⑨ 자동 채움 + 수정 가능, 포스터형 1장 미리보기·인쇄 |
| ⑪ | 발표와 상호 평가 | 발표 순서 4파트 × [내용 / 시간] (8분 발표 + 4분 질의) + 평가 4항목 × 25점 (타깃 정확성·컨셉 창의성·IMC 일관성·실행 가능성) + 한줄 코멘트 | 다른 조 점수 입력 → 강사 화면 집계 |

### 1-4. 반드시 앱에 녹여야 할 교수 원칙 (두 파일 공통)

1. **사실과 판단을 구분한다** — 케이스 C는 모든 문장에 `[공개 조사] [공식 발표] [원자료 집계] [교재 조건] [기획 판단]` 태그, 3-2는 `(가정)` 표기. → 입력칸 옆에 태그 선택기.
2. **숫자는 계산으로 검증한다** — 용량(인원×건수×일수), 평수 합, 예산 합 100%, 1인당 비용, 손익분기. → 앱이 계산하고 교육생은 판단에 집중.
3. **분모를 같은 고객으로** — 상담자 대비 구매·재방문(C④ 노트). → KPI 시트에 분모 입력칸.
4. **하나의 메시지가 끝까지 이어진다** — ③ 슬로건이 ④·⑥·⑩에 반복되는지. → 슬로건 고정 배너 + 일관성 체크.
5. **이전 시트를 옮겨 담는다** — ⑩은 새로 쓰는 게 아님. → 자동 채움.

### 1-5. 기존 자산

저장소의 `dalkom-game-railway-nopin.zip`(3-3 달콤상점 게임)은 **Node 기본 모듈만 쓰는 server.js + 단일 index.html + Railway 볼륨 저장 + team1~6 조별 실습지 API + 강사 화면 + 게임 5종** 구조입니다. 같은 LIFT 과정이므로 이번 앱도 이 구조를 그대로 따르면 배포·운영 방식이 통일됩니다.

# 4. 캠페인 실습 — 활동시트 ①~⑪
- PART 1-2 표의 칸 구성을 그대로 폼으로 만든다. 각 시트 상단에 원자료의 안내 문구(예: "'이런 걸 좋아할 것이다'가 아니라 '이런 상황에 있다'를 적으십시오.")를 그대로 표시.
